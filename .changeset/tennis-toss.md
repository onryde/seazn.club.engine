Tennis records the toss: who serves first (TN-TS-1; owner ruling 233, Seazn Capture S2-7, 2026-11-12: "Toss event first"). Tennis's fold epoch rises to 3 (FOLD_MINOR stays 0), so the server's 426 gate refuses tennis scoring writes from an epoch-2 client (the capture app on engine 7.x included) until it updates.

- **New event `tennis.toss` `{ serving: EntrantId }`** (strict: any other key is refused). It names the entrant who serves the match's first game (ITF Rule 9). It is accepted before `core.start` and after it, only while the toss is open: the match is not over, no toss is recorded, and nothing is scored (no point, game award or set summary). A second toss, or a toss after anything was scored, is refused `WRONG_PHASE`; a toss naming a non-entrant, or a malformed payload, is `INVALID_EVENT`; a toss after the match is decided is the fold's `ALREADY_DECIDED`. A sanction or an interruption does not close it. Undo is `core.void`, which reopens the toss.
- **Serve order follows the toss.** `state.serving` and a new optional `NestedState.opener` (absent until a toss, so every ledger without one folds exactly as before: home serves first) are set to the toss's side, and `serveContext`'s turn walk starts from it, so `serveOrderKnown` stays true when away serves first: games alternate from that side, a tie-break's first server is the side due, the next set opens with its opponent (Rule 5(b)), the match tie-break carries the order in (App VI), and in doubles the side's first-named partner (`pairOrder`) serves its first service game.
- **Pad.** `tennisPadRules.tossOpen(state)` is the fold's own predicate (exported from the nested kernel as `tossOpen`); false with no folded state. `padSpec` offers the toss (`pad.tennis.action.toss`, attribution `side` at `serving`) in a `pre` and a `live` panel (`pad.tennis.panel.toss`), each gated on the same fields. The toss sits at fidelity band 3, the points' band. `NestedToss` (the schema) is exported from the kernel.
- **Ruling 112 applies to it as to any sport event:** a toss after the Start is play, so a walkover is no longer recordable after it (a retirement, a disqualification or a withdrawal is); a toss before the Start is not play. A client that controls the order and wants the walkover kept open sends the toss before `core.start`.
- An epoch-2 engine refuses `tennis.toss` as an unknown event type on write and on replay, so a ledger holding one does not fold there at all.
- Golden: one appended branch stream, tennis `doubles-noad-mtb10#90018` (`tennis.toss_away_serves`), is the epoch-3 witness; no recorded stream moved. `tennis.schema.json` gains the event.
